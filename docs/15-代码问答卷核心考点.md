# 代码问答卷 · 核心考点梳理

**用途**：答辩现场"代码问答"环节，教师通常会指着某段代码问「这里是干什么的 / 为什么这么写」。
本文件按模块整理 **28 个高频问题**，答案都对应本项目真实代码位置。

---

## 一、整体架构（5 问）

### Q1：为什么分四个模块？

`app` / `widget` / `core-data` / `core-domain`。分模块的三个实际收益：
1. `core-domain` 零 Android 依赖 → 算法用纯 JVM 单测（`./gradlew :core-domain:test` 不用模拟器）；
2. `widget` 复用 `core-data` → 组件与主 App 读同一个 Repository，不会出现两套数据；
3. 换持久化实现（比如 SQLDelight）只需改 `core-data`，UI 一行不动。

### Q2：`app` 为什么依赖 `widget`？不是说互不依赖吗？

原设计「互不依赖」是多 APK 场景的写法。单 APK 交付时，**library 的 manifest 只有被 app 依赖才会合并进最终清单**——不依赖的话 `<receiver>` 根本不进 APK，桌面小组件列表里看不到。所以改成 `app → widget`，但守住红线：**widget 不引用 app 任何一个类**（跳转用显式类名字符串）。

### Q3：`AppContainer` 为什么不用 Hilt？

4 个模块、十几个依赖，手写 60 行就够。Hilt 会引入 KSP 全量扫描，增量编译明显变慢，而且答辩要解释 `@Module/@InstallIn/组件生命周期`——收益不匹配。代码在 `app/di/AppContainer.kt`。

### Q4：`DataFactory` 是干什么的？

`:core-data` 把 Room 作为 `implementation` 依赖（不暴露），所以 app 层**看不到 `RoomDatabase` 类型**。`DataFactory` 只暴露领域接口（`WordRepository` 等），数据库实例封在数据层内部。这也修掉过一个编译错误：
`Cannot access 'androidx.room.RoomDatabase' which is a supertype`。

### Q5：为什么 UI 用 RecyclerView 而不是 Compose？

第 2 阶段确实选了 Compose，**第 6 阶段按课程任务要求改成 RecyclerView**。`docs/05` 顶部已加变更说明横幅；Compose 段落的架构结论（分层、状态流）仍然成立，只是 UI 实现方式变了。

## 二、数据库（6 问）

### Q6：`word` 表为什么要有 `spelling_lower` 这一列？

SQLite 的 `COLLATE NOCASE` **只处理 ASCII**（中文、带重音的都不管），而且 Room 无法在 `@Index` 上声明 collation。所以显式存小写列，配 `(book_id, spelling_lower)` 联合唯一索引，一个索引同时支撑：导入去重、字母排序、前缀搜索。

### Q7：`review_log` 为什么存 `interval_ms` 而不是 `next_due_at`？

`next_due_at = reviewed_at + interval_ms`，存两个是冗余且可能不一致。存间隔的好处：可以复现「算法当时给了多长间隔」这个决策，不受时区变化/用户改系统时间影响。见 docs/06 §4.4。

### Q8：删词库为什么不物理删除？

`wordbook.archived_at` 非空 = 已归档：只改一列，单词/复习状态/流水全部保留，**统计不受影响**。彻底删除是独立操作，且只对已归档词库开放，才走外键级联。

### Q9：数据库版本现在是多少？迁移怎么做的？

version **2**。v1→v2 新增 `review_session` + `queue_item` 两张表，用手写 `MIGRATION_1_2`，建表语句与 Room 生成的 `schemas/.../2.json` **逐字一致**（差一个空格 Room 启动就会校验失败）。`fallbackToDestructiveMigration` 保持关闭——不清用户数据。

### Q10：作答涉及几次写库？为什么要事务？

四次：更新 `review_state`、插入 `review_log`、队列项置 ANSWERED、会话计数 +1。四个写用 `db.withTransaction {}` 包住，否则可能「状态更新了但流水没写」，统计与调度直接不一致。

### Q11：队列查询怎么走索引的？

`review_state.next_due_at` 上有索引，队列查询是 `WHERE rs.next_due_at <= :now ... ORDER BY rs.next_due_at ASC LIMIT :limit`，能直接用索引排序，不需要 filesort。

## 三、算法（6 问）

### Q12：为什么 `mod = ease/2.5` 只在 stage ≥ 2 生效？

stage 0/1 的基础间隔是 5 分钟 / 30 分钟。乘个 1.12 毫无意义，还会产生「5 分钟变 5.6 分钟」这种精度噪音。长间隔阶段才需要难度系数拉开差距。代码在 `EbbinghausScheduler.settle()` 的 `when` 分支。

### Q13：抖动为什么只在 stage ≥ 4？

抖动目的是打散「批量导入 → 同时到期 → 队列爆炸」的尖峰，这只会发生在长间隔阶段。短间隔抖 5% 没有业务意义，还会让单测不可复现。

### Q14：为什么把随机源作为构造参数注入？

为了可测试。`EbbinghausScheduler(Random(seed))` 就能确定性复现；测试里还专门开了 20 个种子验证抖动落在 ±5% 区间。

### Q15：掌握判定为什么是「stage ≥ 8 且遗忘 ≤ 2」？

光到阶段不算掌握：反复忘的词即使被推到高阶段，牢固度也不够。加 `lapseCount` 约束是为了避免「刚背完就忘」的词被误判为已掌握而退出队列。

### Q16：三档反馈和四档 `Quality` 的关系？

算法和数据层保留四档（0 忘记 / 1 模糊 / 2 想起 / 3 熟练），界面按课程要求只暴露三档：**不认识 → FORGOT、模糊 → VAGUE、认识 → RECALLED**。`FLUENT` 仍可被快捷操作或将来扩展使用，结算页分布条也能显示它。

### Q17：间隔为什么要夹在 5 分钟 ~ 180 天？

下限防「ease 很低时算出 1 分钟」（会导致疯狂重复）；上限防「连续熟练后间隔滚成几年」（等于永不复习）。

## 四、导入（5 问）

### Q18：为什么不用 opencsv？

需要错误精确到**物理行号**（"第 47 行：meaning 列为空"），第三方库只能告诉你"第几条记录"。行号错了用户在 Excel 里根本定位不到。

### Q19：CSV 解析器怎么处理引号里的逗号？

手写状态机，`inQuotes` 标志：引号内遇到分隔符不拆列，遇到 `""` 转义成一个 `"`，引号内的换行只计数不结束记录。代码在 `CsvParser.kt` 的 `CsvReader.nextRecord()`。

### Q20：非 UTF-8 文件怎么处理？

用 `Charsets.UTF_8.newDecoder().onMalformedInput(REPORT)` 严格解码，GBK 文件在解码阶段就抛 `CharacterCodingException`，转成「请另存为 UTF-8」的提示。不这么做的话，会入库一堆乱码。

### Q21：为什么每 200 行一个事务？

两个目的：① 避免一个事务锁库太久；② 用户取消时**已提交批次完整保留**（对应 AC-05），不会出现"导了一半数据残缺"。

### Q22：导入去重是插入还是更新？

先按 `(book_id, spelling.lowercase())` 查已有词：不存在则插入并初始化 `review_state`；存在则更新释义等字段并刷新 `updated_at`，计入「更新数」。所以同一个文件导两次是「更新 N / 新增 0」。

## 五、小组件（4 问）

### Q23：组件怎么拿到主 App 的数据？

同一进程、同一个 `DancijiyiDatabase` 单例、同一份 db 文件。`WidgetSnapshotLoader` 通过 `DataFactory.wordRepository(context, clock)` 拿 Repository，`observeDueCount(now).first()` 取当前值。**不需要 ContentProvider/AIDL**。

### Q24：`goAsync()` 是干什么的？

`onUpdate` 在主线程执行且系统只给约 10 秒。`goAsync()` 延长广播生命周期，把查库放到 IO 协程，`finally` 必须 `finish()`，否则系统认为广播泄漏。

### Q25：组件刷新有哪几条链路？

四条：① 系统 `onUpdate`（30 分钟兜底）② App 启动写完种子数据 ③ **主 App 写库后 `WidgetSync.notifyDataChanged()` 实时刷新** ④ WorkManager 每日 00:05 跨天归零。`updatePeriodMillis` 的系统下限就是 30 分钟，所以"实时"必须靠 ③。

### Q26：组件上的「已复习」按钮做了什么？

发广播给 `WidgetActionReceiver` → **复用队列引擎**：`openQueue` → 取队首 → `answer(RECALLED)`。这样才会写 `review_log`、更新会话计数，和 App 里点「认识」完全等价。`durationMs` 记 0，统计时用 `duration_ms > 0` 过滤掉。

## 六、工程化（4 问）

### Q27：权限降级怎么设计的？

| 权限 | 拒绝后 |
|---|---|
| `POST_NOTIFICATIONS` | 提示「用桌面小组件替代」+ 去系统设置 |
| `READ_EXTERNAL_STORAGE`（≤API32 兼容通道） | 降级为手动添加单词 |
| 存储权限（主导入） | **根本不申请**，用 SAF |

核心思路：**能少要一个权限就少要一个**。SAF 让「存储权限被拒」这条降级路径直接消失。

### Q28：崩溃了怎么办？

`Thread.setDefaultUncaughtExceptionHandler` 写 `crash.log`（只保留最近一次）后交回系统；下次启动 `MainActivity` 读取并弹「上次运行异常退出」+ 堆栈摘要。**故意不做自动重启**——演示时会掩盖问题。

## 七、可能的追问（3 问）

### Q29：这个项目最难的三个点是什么？

1. **AGP 9 的破坏性变更**：Android 模块不得再 apply `kotlin-android`（已内置），`android.defaults.buildfeatures.buildconfig` 被移除——都是构建期直接失败，没有文档可查，靠报错反推；
2. **`date_key` 唯一索引导致的必崩缺陷**：当天复习完再来新词会崩溃，改成"重开会话追加队列项"；
3. **小组件实时性**：系统给的 30 分钟下限满足不了需求，得自己做写库后主动广播 + 跨天 WorkManager。

### Q30：如果给你更多时间，你会改什么？

- 主页从"功能面板"改成正经首页（现在还是调试面板）；
- 组件支持 4×2 宽版 + 按实例配置订阅词库；
- 补 `androidTest`（Espresso/Robolectric），把数据库读写也纳入自动化；
- 提醒时间挪到设置页（现在是常量 21:00）。

### Q31：你怎么保证交付质量？

四层：① 算法/解析/定时共 24 个单测全绿；② Room 的 `@Query` 由 KSP 在**编译期**校验 SQL（真拦下过 1 个错误）；③ 全流程静态走查（发现 10 个 Bug 并全部修复，见 `docs/08`）；④ 32 条手工回归用例待真机执行。
