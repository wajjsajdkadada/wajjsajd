# 联调问题与修复清单

**文档版本**：v1.0（第 14 阶段产出，对应提交 #14）
**联调范围**：导入词库 → 生成复习队列 → 复习作答 → 记忆更新 → 小组件同步 → 通知提醒

---

## 0. 联调方式说明

本机模拟器（AVD `Medium_Phone_API_37.0`）因 WHPX 虚拟化不可用无法启动，因此"全流程联调"采用
**静态走查 + 编译期校验 + 单测覆盖**三重方式：

1. **数据流走查**：沿「导入 → 队列 → 作答 → 统计 → 组件 → 通知」逐跳核对写入方与读取方；
2. **编译期校验**：Room 的 `@Query` 在 KSP 阶段就会做 SQL 语法与列名校验（本次拦下 1 个真 bug）；
3. **单元测试**：算法与解析器共 20 个用例，覆盖阶段边界与文件异常分支。

下面 7 条是这次走查**实际发现并修复**的问题，不是凑数的"已知限制"。

---

## 1. 【严重】当天会话完成后又有新到期词 → 唯一索引冲突崩溃

### 现象

1. 上午把今日 20 个词全部答完 → 会话 `status = COMPLETED`；
2. 下午：顺延的 8 个词到点，或又导入了 50 个新词（新词 `next_due_at = 导入时刻`，立即到期）；
3. 再次进入复习页 → **崩溃**：

```
android.database.sqlite.SQLiteConstraintException:
UNIQUE constraint failed: review_session.date_key (code 2067)
```

### 根因

`review_session.date_key` 上有唯一索引（保证「一天一个会话」），而 `openQueue` 只查
`status = 'ACTIVE'` 的会话；当天已有 COMPLETED 会话时它认为"今天没会话"，于是尝试
`INSERT` 第二条同 `date_key` 的记录 → 撞唯一索引。

### 修复

`openQueue` 增加第 2 个分支：**重开当天已有会话并追加队列项**，而不是新建。

```kotlin
val existing = queueDao.findSessionByDate(dateKey)
if (existing != null) {
    val candidates = queueDao.pickQueueCandidates(nowMillis, planned)
    db.withTransaction {
        val start = queueDao.maxPosition(existing.id) + 1
        val rowIds = queueDao.insertItemsIgnoreDuplicates(...)   // 见 §2
        added = rowIds.count { it >= 0 }
        queueDao.reopenSession(existing.id, added, existing.deferredCount + deferred)
    }
}
```

配套 DAO：

| 方法 | 作用 |
|---|---|
| `findSessionByDate(dateKey)` | 取当天最近一次会话（含已完成） |
| `maxPosition(sessionId)` | 追加时位置从已有最大 position+1 开始 |
| `reopenSession(id, added, deferred)` | `status='ACTIVE'`、`ended_at=null`、计划数累加 |

**为什么用"重开"而不是"drop 掉唯一索引"**：唯一索引本身是"一天一个会话"的业务约束，
重开语义更贴合真实场景（同一天可能分两次复习），也避免了再做一次 v2→v3 迁移的风险。

## 2. 【中】重开会话时，被「跳过」的词会撞 `(session_id, word_id)` 唯一索引

### 现象

跳过的词仍处于到期状态（未作答、`next_due_at` 未变），重开会话时会被再次选为候选，
插入时违反 `queue_item` 上的 `(session_id, word_id)` 唯一约束。

### 修复

新增 `insertItemsIgnoreDuplicates`（`@Insert(onConflict = IGNORE)`），
返回的 rowId 中 `-1` 表示被忽略；`added` 只统计真正插入的行。

若 `added == 0`（候选词全在会话里），返回"无新任务"，界面显示"今日没有到期的单词"而不是空队列。

---

## 3. 【中】小组件「已复习」的 0 毫秒污染了平均作答耗时

### 现象

结算页显示"平均 0.3 秒/词"——因为小组件快捷操作记 `durationMs = 0`，而平均耗时用的是
`AVG(duration_ms)`，0 值会把均值整体拉低。

### 修复

统计口径加过滤条件：

```sql
SELECT COALESCE(AVG(duration_ms), 0)
  FROM review_log
 WHERE session_id = :sessionKey AND duration_ms > 0
```

**为什么不改写入而是改查询**：`duration_ms = 0` 是"没有作答过程"的**真实记录**，
应该保留（将来可用于区分"快捷过词"与"正常作答"），只是不该参与均值计算。

## 4. 【中】通知权限未授予时，`notify()` 静默失败

### 现象

Android 13+ 未授予 `POST_NOTIFICATIONS` 时，`NotificationManagerCompat.notify()` **不抛异常、
也不显示通知**。用户点了"开启提醒"却永远收不到，会以为功能坏了。

### 修复

1. `ReminderNotifier.show()` 改为返回 `Boolean`，先显式检查权限再发；
2. `ReminderWorker` 收到 `false` 时写警告日志，不重试（重试也发不出去）；
3. UI 侧完整权限流程：
   - 已授权 → 直接登记任务；
   - 拒绝过（`shouldShowRequestPermissionRationale`）→ 先弹 rationale 说明"用途 + 不给也能用"；
   - 再次拒绝 → 弹**降级提示**：「每日提醒不会弹出，可把小组件放到桌面，效果一样」，
     并给"去系统设置"的直达入口。

## 5. 【轻】`ReviewViewModel` 残留已废弃的 `dailyLimit` 参数

### 现象

每日上限已经改为从 `AlgorithmConfig` 读取（第 8 阶段），但 ViewModel 里还留着
`dailyLimit: Int = DEFAULT_DAILY_LIMIT` 参数与常量，属于死代码，容易让人误以为改它能生效。

### 修复

删除该参数与 `DEFAULT_DAILY_LIMIT` 常量，上限只由算法参数决定（设置页单一入口）。

---

## 6. 【编译期】Room `@Query` 参数少写冒号 → KSP 直接报错

### 现象

```
[ksp] QueueDao.kt:51: There is a problem with the query:
[SQLITE_ERROR] SQL error or missing database (no such column: deferred)
[ksp] Unused parameter: deferred
```

### 根因

`UPDATE review_session SET ... deferred_count = deferred ...` —— 绑定参数写成了列名形式
（少一个 `:`）。

### 修复

`deferred_count = :deferred`。

> **这条值得记录**：如果没有 KSP 的编译期 SQL 校验，这个错误要到运行时 `SQLiteException`
> 才暴露，而且只在"当天重开第二次"这种边缘路径触发，很难复现。这正是选 Room 而非裸写
> SQLiteOpenHelper 的收益。

## 7. 【编译期】小组件取单词拼写多了一层属性访问

### 现象

`WidgetActionReceiver` 里写 `head.word.word.word.spelling` → `Unresolved reference 'word'`。

### 根因

`ReviewQueueItem.word` 的类型是 `WordWithState`，而 `WordWithState.word` 才是 `Word`。
所以只有两层：`head.word.word.spelling`。

### 修复

改为两级访问。**顺带说明**这个命名确实容易误解（`item.word.word`），但它是"队列项包含
词+状态，其中词又是完整词对象"的自然结果；若改成 `item.wordState.word` 会更清晰，
留到重构阶段处理（不在本阶段改动公开模型，避免影响其它调用点）。

## 8. 修复后的全流程校验表

| 环节 | 触发 | 写库 | 观察点 | 状态 |
|---|---|---|---|---|
| 导入词库 | 选择 CSV → 导入 | `word` + `review_state`（next_due_at = now） | 导入结果页四类计数 | ✅ |
