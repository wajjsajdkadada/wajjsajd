# Room 数据库数据模型设计

**文档版本**：v1.0（第 2 阶段产出，对应提交 #2）
**设计目标**：支撑「导入 → 调度 → 作答 → 统计」全链路；**算法状态与复习痕迹都可追溯**，任何一次调度结果都能解释成「哪个词、第几次、什么反馈、怎么算出来的」。
**落地阶段**：第 5 次提交（`feat(data)`）把本文件的实体与 DAO 写成 Kotlin 文件。

---

## 1. 设计原则

| 原则 | 具体落实 |
|---|---|
| **单一数据源** | 界面不缓存数据，全部经 Room + Flow 回流；小组件与主 App 读同一个库文件 |
| **算法状态与流水分离** | `review_state`＝当前状态（1 词 1 行，可覆盖）；`review_log`＝历史流水（只增不改），统计与追溯都查流水 |
| **时间统一 Long** | 全部时间列存 epoch millis（`Long`），避免时区与字符串比较问题；展示层再格式化 |
| **能重算的就不存** | 正确率、平均间隔、掌握率都不建冗余列，实时聚合；只有「掌握」判定结果落 `is_mastered`（要参与索引查询） |
| **破坏性操作留痕** | 删除词库级联删词，但 `import_record` 保留（导入历史不因删词库而丢失，用于「上次导入了什么」） |
| **列名 snake_case** | 与 SQL 习惯一致，避免 Kotlin 属性名直接映射导致迁移脚本难写 |

```
  │  import_record   │                    │     setting      │
  │  id (PK)         │                    │  key (PK)        │
  │  book_id (FK→?) │                    │  value           │
  │  file_name       │                    └──────────────────┘

  └──────────────────┘                     （纯键值配置）
```

**关系说明**

| 关系 | 基数 | 级联行为 |
|---|---|---|
| `wordbook` → `word` | 1 : N | `ON DELETE CASCADE`：删词库即删其所有单词 |
| `word` → `review_state` | 1 : 1（共享主键） | `ON DELETE CASCADE`：单词没了状态也没了 |
| `word` → `review_log` | 1 : N | `ON DELETE CASCADE`：删词时流水一并清除（**这是有意的取舍**，见 §6.2） |
| `wordbook` → `import_record` | 1 : N（弱引用） | **不建外键**，仅存 `book_id` 值；词库删除后导入记录仍保留，`book_id` 变为悬空值，展示为「已删除的词库」 |

## 4. 表结构详解

### 4.1 `wordbook` —— 词库

| 列名 | 类型 | 约束 | 默认 | 说明 |
|---|---|---|---|---|
| `id` | INTEGER | PK, AUTOINCREMENT | — | 词库 ID |
| `name` | TEXT | NOT NULL, 长度 1–32 | — | 词库名，如「四级核心 1600」；同一设备允许重名（不做唯一约束，避免导入时因重名失败） |
| `description` | TEXT | NULL, ≤128 | NULL | 备注，可空 |
| `is_builtin` | INTEGER(Boolean) | NOT NULL | 0 | 1＝内置示例词库；影响 UI 是否显示「恢复示例词库」 |
| `created_at` | INTEGER(Long) | NOT NULL | now | 创建时间（epoch millis） |
| `archived_at` | INTEGER(Long) | NULL | NULL | **归档时间**。非空＝已归档。归档后该词库退出切换器与复习队列，但其单词 / 复习状态 / 复习流水**全部保留**，统计继续计入；彻底删除是仅对已归档词库开放的独立操作 |

**业务约束（在 Repository 层强制）**：词库名 trim 后非空；删除内置词库允许（`docs/01` FR-1.10）；**所有业务查询必须显式带 `WHERE archived_at IS NULL`**，`archived_at` 非空的词库不得出现在切换器与复习队列中（删除语义见 §6.2）。词库表 < 100 行，`archived_at` 不单独建索引。

### 4.2 `word` —— 单词（核心实体）

| 列名 | 类型 | 约束 | 默认 | 说明 |
|---|---|---|---|---|
| `id` | INTEGER | PK, AUTOINCREMENT | — | 单词 ID，全局唯一（跨词库不重复） |
| `book_id` | INTEGER | NOT NULL, FK→`wordbook.id` CASCADE | — | 所属词库 |
| `spelling` | TEXT | NOT NULL, 长度 1–64 | — | 原始拼写（保留大小写，如 `Abandon`、`iPhone`） |
| `spelling_lower` | TEXT | NOT NULL, 长度 1–64 | — | `spelling.lowercase()` 的去重/搜索键。**为什么不依赖 `COLLATE NOCASE`**：SQLite 的 `NOCASE` 只处理 ASCII，且 Room 无法在 `@Index` 上声明 collation，用显式小写列最稳 |
| `phonetic` | TEXT | NULL, ≤256 | NULL | 音标，如 `/əˈbændən/`；导入可缺 |
| `meaning` | TEXT | NOT NULL, 长度 1–512 | — | 释义，含词性前缀（`v. 放弃；抛弃`） |
| `example` | TEXT | NULL, ≤256 | NULL | 英文例句 |
| `example_translation` | TEXT | NULL, ≤256 | NULL | 例句译文；有 `example` 无译文时允许 |
| `created_at` | INTEGER(Long) | NOT NULL | now | 首次导入时间 |
| `updated_at` | INTEGER(Long) | NOT NULL | now | 最近一次被导入更新/手动编辑的时间（判断「重复导入是否真的更新」） |

**索引**

| 索引 | 列 | 唯一 | 支撑的查询 |
|---|---|---|---|
| `index_word_book_id_spelling_lower` | (`book_id`, `spelling_lower`) | **是** | ① 导入去重 upsert ② 词库内按字母排序 ③ 前缀搜索 `LIKE 'abc%'` |
| （隐含）`book_id` 前缀 | 由上面的联合索引左侧覆盖 | — | 不再单独建 `book_id` 索引，避免冗余写放大 |

> **联合索引顺序的理由**：`(book_id, spelling_lower)` 而非 `(spelling_lower, book_id)` —— 本项目所有查询都先限定词库，`book_id` 选择性虽低但作为前导列可让「同一词库的字母序」直接走索引扫描，无需额外排序。

### 4.3 `review_state` —— 记忆状态（每词 1 行）

| 列名 | 类型 | 约束 | 默认 | 说明 |
|---|---|---|---|---|
| `word_id` | INTEGER | **PK**, FK→`word.id` CASCADE | — | 与单词共享主键（1:1 关系最省空间的建模方式） |
| `stage` | INTEGER | NOT NULL, 0 ≤ x ≤ 9 | 0 | 艾宾浩斯-Δ 阶段，对应 `docs/01` §5.4.1 的间隔表 |
| `ease_factor` | REAL | NOT NULL, 1.30–2.80 | 2.50 | 难度系数，随四档反馈增减 |
| `lapse_count` | INTEGER | NOT NULL, ≥0 | 0 | 累计「忘记」次数，参与掌握判定（`stage≥8 且 lapse≤2`） |
| `review_count` | INTEGER | NOT NULL, ≥0 | 0 | 累计复习次数（`=0` 表示新词，详情页据此显示「新词」Chip） |
| `last_reviewed_at` | INTEGER(Long) | NULL | NULL | 上次作答时间；`NULL` ＝ 从未复习 |
| `next_due_at` | INTEGER(Long) | NOT NULL, 建索引 | now | 下次到期时间。**队列查询的唯一排序键** |
| `is_mastered` | INTEGER(Boolean) | NOT NULL | 0 | 掌握标记：算法自动判定（`stage≥8 且 lapseCount≤2`）或用户在详情页手动标记 |

**索引**

| 索引 | 列 | 支撑的查询 |
|---|---|---|
| `index_review_state_next_due_at` | (`next_due_at`) | 今日队列：`WHERE next_due_at <= :now ORDER BY next_due_at LIMIT :limit`；词库到期数聚合 |

> 不建 `(is_mastered, next_due_at)` 联合索引：掌握率统计是**全表聚合**（`COUNT(*) WHERE is_mastered=1` / `COUNT(*)`），50000 行全表扫描在课设数据量下 < 15ms，加索引反而增加写负担。若第 13 阶段实测慢，再补。

### 4.4 `review_log` —— 记忆记录（复习流水，只增不改）

**这是「记忆记录实体」的核心表**：每作答一次写一行，既是统计的数据源，也是「系统为什么这么排」的解释依据。

| 列名 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `id` | INTEGER | PK, AUTOINCREMENT | 流水 ID |
| `word_id` | INTEGER | NOT NULL, FK→`word.id` CASCADE | 哪个词 |
| `quality` | INTEGER | NOT NULL, 0–3 | 反馈：0 忘记 / 1 模糊 / 2 想起 / 3 熟练（与 UI 四档一一对应） |
| `prev_stage` | INTEGER | NOT NULL | 作答前 stage（用于时间线展示「阶段 2 → 3」） |
| `next_stage` | INTEGER | NOT NULL | 作答后 stage |
| `prev_ease` | REAL | NOT NULL | 作答前 easeFactor（用于算法回放与调参对比） |
| `next_ease` | REAL | NOT NULL | 作答后 easeFactor |
| `interval_ms` | INTEGER(Long) | NOT NULL | **本次结算出的下次间隔**（毫秒）。注意不是 `next_due_at`，存间隔便于直接验证「算法给的间隔是否合理」，不受时区/时钟漂移影响 |
| `duration_ms` | INTEGER(Long) | NOT NULL, ≥0 | 本题作答耗时（从翻牌到点击按钮）；完成页「平均 4.2 秒」由它聚合 |
| `session_id` | TEXT | NOT NULL | 一次复习会话（进入复习页到完成）的 UUID；完成页统计与「撤销」都按它聚合 |
| `reviewed_at` | INTEGER(Long) | NOT NULL, 建索引 | 作答时间 |

**索引**

| 索引 | 列 | 支撑的查询 |
|---|---|---|
| `index_review_log_word_id_reviewed_at` | (`word_id`, `reviewed_at`) | 详情页时间线：`WHERE word_id=? ORDER BY reviewed_at DESC LIMIT 20` |
| `index_review_log_reviewed_at` | (`reviewed_at`) | 统计面板：`WHERE reviewed_at >= ?` 聚合正确率、复习次数；清理历史 `DELETE WHERE reviewed_at < ?` |

**为什么不存 `next_due_at` 而存 `interval_ms`**：`next_due_at = reviewed_at + interval_ms`，存两者是冗余且可能不一致；存间隔还能在「用户改了时区/系统时间」后仍能复现算法的决策。

### 4.5 `import_record` —— 导入记录

| 列名 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `id` | INTEGER | PK | |
| `book_id` | INTEGER | NULL（弱引用） | 目标词库；词库删除后此值悬空，展示为「已删除的词库」 |
| `file_name` | TEXT | NOT NULL, ≤128 | 用户选择的文件名（SAF 的 `displayName`），只存名字不存路径（URI 授权不持久化） |
| `format` | TEXT | NOT NULL, `CSV`/`JSON` | 嗅探出的格式 |
| `total` | INTEGER | NOT NULL | 总行数（不含表头） |
| `inserted` | INTEGER | NOT NULL | 新增数 |
| `updated` | INTEGER | NOT NULL | 更新数（拼写已存在） |
| `skipped` | INTEGER | NOT NULL | 跳过数（空行） |
| `failed` | INTEGER | NOT NULL | 失败数（校验不通过） |
| `failed_detail_json` | TEXT | NULL | 失败明细 JSON（`[{"line":47,"reason":"缺少 meaning 列"}]`），**只存前 100 条**，避免单行超长 |
| `status` | TEXT | NOT NULL, `DONE`/`CANCELED`/`FAILED` | 用于区分「取消」与「完成」 |
| `created_at` | INTEGER(Long) | NOT NULL | |

### 4.6 `setting` —— 键值配置

| 列名 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `key` | TEXT | **PK** | 见下表 |
| `value` | TEXT | NOT NULL | 一律存字符串，读取方负责解析（避免 6 种类型的列转换器） |

**已定义的键**

| key | 类型 | 默认 | 说明 |
|---|---|---|---|
| `reminder.enabled` | Boolean | `false` | 提醒开关 |
| `reminder.time` | String `"21:00"` | `21:00` | 提醒时刻（`HH:mm`） |
| `algo.daily_review_limit` | Int | `50` | 每日复习上限（20–200） |
| `algo.daily_new_limit` | Int | `20` | 每日新词上限（5–100） |
| `algo.jitter_enabled` | Boolean | `true` | 间隔抖动开关 |
| `algo.version` | String | `"ebbinghaus-delta-v1"` | 算法版本（参数不兼容变更时提示重算） |
| `last_book_id` | Long | `-1` | 上次打开的复习词库 |

> 小组件的「订阅哪些词库」**不放这张表**，放 `SharedPreferences`（`widget_books_<appWidgetId>`）。原因：组件配置键的数量随组件实例增长，属于系统组件自己的元数据，用键值表会污染业务表且删除组件时不便清理。

## 5. 索引与查询映射

| 界面/功能 | 查询要点 | 走的索引 |
|---|---|---|
| 词库切换器（含到期数） | `SELECT wb.id, wb.name, COUNT(w.id), SUM(CASE WHEN rs.next_due_at <= :now THEN 1 ELSE 0 END) FROM wordbook wb LEFT JOIN word w ON w.book_id = wb.id LEFT JOIN review_state rs ON rs.word_id = w.id WHERE wb.archived_at IS NULL GROUP BY wb.id` | `idx_word_book_id_spelling_lower`（左侧）+ `idx_review_state_next_due_at` |
| 今日复习队列 | `SELECT ... FROM word JOIN review_state rs ON ... WHERE rs.next_due_at <= :now AND rs.is_mastered=0 ORDER BY rs.next_due_at ASC LIMIT :limit` | `idx_review_state_next_due_at` |
| 顺延数量 | `SELECT COUNT(*) FROM review_state WHERE next_due_at<=:now` 减去队列已取 | 同上 |
| 单词列表（字母序） | `WHERE book_id=:id ORDER BY spelling_lower ASC` | 联合唯一索引可直接顺序扫描（**无需 filesort**） |
| 单词搜索 | `WHERE book_id=:id AND spelling_lower LIKE :kw || '%'` | 联合唯一索引（前缀匹配，无前导通配符） |
| 详情页时间线 | `WHERE word_id=:wid ORDER BY reviewed_at DESC LIMIT 20` | `idx_review_log_word_id_reviewed_at` |
| 统计面板 | `SELECT quality, COUNT(*), AVG(duration_ms) FROM review_log WHERE reviewed_at>=:since GROUP BY quality` | `idx_review_log_reviewed_at` |
| 小组件快照 | 两个查询：到期数 + `LIMIT 3` 的队首词 | `idx_review_state_next_due_at` |
| 清理历史 | `DELETE FROM review_log WHERE reviewed_at < :cutoff` | `idx_review_log_reviewed_at` |

**禁止的查询**：`LIKE '%kw%'`（前导通配符，全表扫 + 无法用索引）；全表 `SELECT * FROM word`（50000 行会进内存，列表必须带 `LIMIT` 或由 `LazyColumn` + 分页流式读取）。

## 6. 事务与一致性

### 6.1 事务边界

| 操作 | 事务范围 | 失败处理 |
|---|---|---|
| 导入（每 200 行） | 单事务内：批量 upsert `word` + 对应 `review_state` 初始化 | 该批次回滚，已提交批次保留；结果页标注「第 N 批失败」 |
| 作答（单题） | 单事务内：`UPDATE review_state` + `INSERT review_log` | **必须原子**：否则会出现「状态变了但没流水」或反之，统计与调度不一致 |
| 归档词库 | `UPDATE wordbook SET archived_at = :now WHERE id = ?`，不动任何子表 | 统计与流水不受影响 |
| 恢复归档词库 | `UPDATE wordbook SET archived_at = NULL WHERE id = ?` | 其单词按原 `next_due_at` 重新进入队列 |
| 彻底删除（仅已归档） | `DELETE FROM wordbook WHERE id = ? AND archived_at IS NOT NULL`，靠外键级联删词 / 状态 / 流水 | 需输入「确认」；Room 外键默认开启 |
| 撤销上一题 | 单事务内：用**内存快照**恢复 `review_state` + `DELETE` 对应 `review_log` | 仅支持 1 步；快照在 ViewModel 内存中，不落库（重启后不可撤销） |
| 清空复习历史 | `DELETE FROM review_log`，不动 `review_state` | 独立事务 |

### 6.2 两级删除：归档（默认）与彻底删除

需求方明确要求「删除词库不能伤到总体统计」，因此**默认操作是归档，而不是删除**：

| 操作 | SQL | 影响 | 可恢复 |
|---|---|---|---|
| **归档**（默认） | `UPDATE wordbook SET archived_at = :now WHERE id = :id` | 该词库从切换器消失、其单词不再进入复习队列；单词 / 状态 / 流水**全部保留**，统计继续计入 | ✅ 设置页「恢复」 |
| **彻底删除**（仅已归档） | `DELETE FROM wordbook WHERE id = :id AND archived_at IS NOT NULL` | 外键级联清除其单词、复习状态、复习流水 | ❌ 需输入「确认」 |

**为什么 `review_log` 仍然保留 `ON DELETE CASCADE`**：流水离开单词就失去上下文（无法在时间线展示，也无法解释调度），留着只会污染统计分母。但因为有了「归档」这一层，日常操作几乎不会触发级联删除——**统计保护靠归档实现，而不是靠取消级联**。

**代价与边界**：归档词库仍占存储，其中单词若已到期会一直「欠着」不复习。缓解：设置页在归档项旁显示「已归档 N 天」，并提示可彻底删除。
## 7. 类型转换与 Kotlin 实体设计稿

**不建 TypeConverter**：实体层全部用基本类型（`Long`/`Int`/`Double`/`String`/`Boolean`），时间即 `Long`。领域层用 `java.time.Instant`，在 Mapper 里转换一次。

> 这样做的收益：迁移脚本、`sqlite3` 手工排查、Room 的 schema JSON 都最直观；代价是多一层 Mapper（本来也需要，用于 DTO→领域模型）。

```kotlin
// 设计稿：第 5 次提交落地到 :core-data/local/entity/
@Entity(tableName = "wordbook")
data class WordbookEntity(
    @PrimaryKey(autoGenerate = true) val id: Long = 0,
    val name: String,
    val description: String? = null,
    @ColumnInfo(name = "is_builtin") val isBuiltin: Boolean = false,
    @ColumnInfo(name = "created_at") val createdAt: Long,
)

@Entity(
    tableName = "word",
    foreignKeys = [ForeignKey(
        entity = WordbookEntity::class,
        parentColumns = ["id"],
        childColumns = ["book_id"],
        onDelete = ForeignKey.CASCADE,
    )],
    indices = [Index(value = ["book_id", "spelling_lower"], unique = true)],
)
data class WordEntity(
    @PrimaryKey(autoGenerate = true) val id: Long = 0,
    @ColumnInfo(name = "book_id") val bookId: Long,
```

## 8. DAO 契约草案

```kotlin
@Dao
interface WordDao {
    @Query("""
        SELECT w.*, rs.stage, rs.ease_factor, rs.next_due_at, rs.is_mastered
        FROM word w INNER JOIN review_state rs ON rs.word_id = w.id
        WHERE w.book_id = :bookId
          AND (:keyword = '' OR w.spelling_lower LIKE :keyword || '%')
        ORDER BY
          CASE WHEN :sort = 'DUE'  THEN rs.next_due_at END ASC,
          CASE WHEN :sort = 'AZ'   THEN w.spelling_lower END ASC,
          CASE WHEN :sort = 'NEW'  THEN w.created_at END DESC
    """)
    fun observeWords(bookId: Long, keyword: String, sort: String): Flow<List<WordWithState>>

    @Query("SELECT COUNT(*) FROM review_state WHERE next_due_at <= :now AND is_mastered = 0")
    fun observeDueCount(now: Long): Flow<Int>
}

@Dao
interface ReviewDao {
    @Query("""
        SELECT w.*, rs.stage, rs.ease_factor, rs.review_count, rs.last_reviewed_at
        FROM word w INNER JOIN review_state rs ON rs.word_id = w.id
        WHERE rs.next_due_at <= :now AND rs.is_mastered = 0
        ORDER BY rs.next_due_at ASC
        LIMIT :limit
    """)
    suspend fun loadDueQueue(now: Long, limit: Int): List<WordWithState>

    @Update suspend fun updateState(state: ReviewStateEntity)
    @Insert suspend fun insertLog(log: ReviewLogEntity): Long
    @Query("DELETE FROM review_log WHERE id = :logId") suspend fun deleteLog(logId: Long)

    // 作答结算：状态 + 流水必须同一事务
    @Transaction
    suspend fun applyAnswer(state: ReviewStateEntity, log: ReviewLogEntity) {
        updateState(state)
        insertLog(log)
    }
}
```

**约定**

- 查询返回 `Flow` 的用于界面观察；`suspend` 返回值的用于一次性取数（队列生成、小组件快照）。
- 组合 `Word` + `ReviewState` 用 `@Embedded`/关系类，不建视图（Room 的关系查询已足够，加 View 会提高迁移成本）。
- 所有写方法为 `suspend` 或 `@Transaction`，**禁止主线程访问**（Room 默认 `allowMainThreadQueries=false`）。

## 10. 容量估算（验证 NFR-5「< 20MB」）

| 表 | 单行估算 | 规模 | 占用 |
|---|---|---|---|

## 12. 与算法层的接口

```kotlin
// :core-domain —— 输入当前状态与反馈，输出新状态（纯函数，无副作用）
data class ReviewState(
    val wordId: Long,
    val stage: Int,
    val easeFactor: Double,
    val lapseCount: Int,
    val reviewCount: Int,
    val lastReviewedAt: Instant?,
    val nextDueAt: Instant,
    val isMastered: Boolean,
)

data class ScheduleResult(
    val nextState: ReviewState,
    val interval: Duration,   // 落库为 review_log.interval_ms
    val transition: String,   // 用于时间线展示："阶段 2 → 3"、"忘记，回退 2 档"
)

interface ReviewScheduler {
    fun schedule(state: ReviewState, quality: Quality, now: Instant): ScheduleResult
}
```

**映射关系**：`ReviewStateEntity` ←→ `ReviewState` 由 `:core-data` 的 Mapper 负责；`:core-domain` 不依赖任何 Room 类型（保证 `:core-domain:test` 无需 Android 环境）。
